    Purpose:      Notifies operator of victim actions

    Data:         Full mc{} object (see EXFILTRATED DATA below)
    Purpose:      Sends stolen card data to server

  Event: "submitCode"
    Data:         Verification code entered by victim
    Purpose:      Forwards 3DS/OTP code to operator for real-time relay

## SERVER → CLIENT EVENTS (message handler)

  Event: "config" / "userSiteConfig"
    Purpose:      Initial page configuration, branding, text strings
    Data:         Full site config including Bulgarian text, fine amounts, etc.

  Event: "message" (decrypted)
    Status values that trigger page transitions:
      "waitVerificationPhoneCode"     → Navigate to PhoneCode (SMS code entry)
      "waitVerificationExpressCvv"    → Navigate to ExpressCvv (re-enter CVV)
      "waitVerificationCustomCode"    → Navigate to CustomCode (arbitrary code)
      "waitVerificationEmail"         → Navigate to EmailCode (email code entry)
      "complete" + "success"          → Navigate to Success page
      "wait"                          → Show loading/waiting indicator
      error status                    → Show card error message

    The OPERATOR controls which page the victim sees next.
    This enables real-time 3D Secure bypass:
      1. Victim submits card → operator receives data
      2. Operator initiates real transaction with stolen card
      3. Bank sends 3DS SMS to victim's phone
      4. Operator sends "waitVerificationPhoneCode" to victim's browser
      5. Victim enters the real SMS code thinking it's for the fine
      6. Operator receives code via "submitCode" event
      7. Operator completes the real transaction
